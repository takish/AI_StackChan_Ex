# Jina Search の認証必須化に対応する

## 背景

ユーザーが「ニュース教えて」「天気は？」と話しかけても適切な応答が返ってこない問題があった。原因を切り分けたところ、Jina の Search API (`s.jina.ai`) が **2024 年後半より認証必須化**されていることが判明した。

```
HTTP/2 401
{"name":"AuthenticationRequiredError",
 "message":"Authentication is required to use this endpoint. Please provide a valid API key via Authorization header."}
```

既存実装 (`firmware/src/llm/FunctionCall/tools/JinaSearch.cpp`) は Authorization ヘッダなしで叩いているため、必ず 401 を受け取り「検索に失敗しました（HTTP 401）」を LLM に返していた。

## やること

1. `JinaSearch` に `jina_set_api_key(const String&)` を追加し、HTTP リクエスト時に `Authorization: Bearer <key>` を付与する
2. `ex_config_s` に `jina.api_key` フィールドを追加し、`SC_ExConfig.yaml` 経由で SD カードから読み込む
3. composition root (`main.cpp`) で起動時に 1 回 `jina_set_api_key()` を呼んで注入
4. キー未設定 / 401 / 403 を受けた場合は LLM 向けに「APIキーを確認してください」とわかりやすいメッセージを返す

## やらないこと

- `FunctionCall.cpp` 内の旧 `static jina_search` の削除
  - 新 Tool が登録されていれば `exec_calledFunc` の registered tools 優先ロジックで通らない（dead code）
  - 削除は別 PR の boy scout scope。今回は触らない
- 親クラス `StackchanSystemConfig` (外部ライブラリ) の `api_keys_s` 構造体の拡張
  - 変更範囲が大きく、本家の責務でない
  - AI_StackChan_Ex 専用の `ex_config_s` に持たせる方が筋

## キーの保管場所

シークレット情報は **SD カード上の `Copy-to-SD/app/AiStackChanEx/SC_ExConfig.yaml`** に書く（git にはコミットされない `Copy-to-SD/` だがリポジトリのサンプルに反映済みなので、実機キーは SD カード上で直接編集する運用）。

```yaml
jina:
  api_key: "jina_xxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

## レイヤー上の位置づけ

- `jina_set_api_key()` は **静的状態のセッター**で、レイヤード設計的にはグローバル状態の追加にあたる。
  - 本来は `JinaSearch` クラス化して各 Tool のコンストラクタで受け取る方が綺麗
  - ただし API キーは起動後変わらず、変更頻度が極めて低いため、簡素なクロージャ的状態として許容する
  - 将来的に複数の検索プロバイダ（Brave / Tavily / Bing 等）が増えたタイミングで `SearchClient` 抽象化を検討する
- 注入は composition root (`main.cpp`) からのみ行う（`new ToolBase()` の直前）

## エラーハンドリング

- `s_jina_api_key` が空 → ヘッダ未付加 → 401 → わかりやすいメッセージ
- 401 / 403 → "検索サービスの認証に失敗しました。APIキーを確認してください。"
- その他の HTTP エラー → 既存メッセージ "検索に失敗しました（HTTP xxx）。"
- JSON パース失敗 / 結果 0 件は既存通り

## 動作確認手順

1. SD カードを取り出して Mac に挿入
2. `/app/AiStackChanEx/SC_ExConfig.yaml` の `jina.api_key` に実キーを貼り付け
3. SD カードを CoreS3 に戻して起動
4. シリアルログで `[jina] api_key set (len=NN)` が出ることを確認
5. 「最新のAIニュース教えて」「東京の天気は？」と発話
6. シリアルログで `[get_news] topic=...` → `[jina] GET https://s.jina.ai/?q=...` → HTTP 200 を確認
7. 検索結果が読み上げられれば成功
